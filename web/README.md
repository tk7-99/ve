# DAZZA Web

واجهة ويب أولية لدَزّة، تستخدم تسجيل الدخول برمز تحقق يُرسل إلى البريد الإلكتروني، ثم تنشئ جلسة Matrix للمحادثات.

## الخدمات المطلوبة قبل تشغيل تسجيل الدخول

- بوابة FastAPI منشورة عبر HTTPS.
- خادم Matrix/Synapse منشور عبر HTTPS.
- Redis وPostgreSQL لبوابة الهوية.
- حساب Resend مع API key وعنوان إرسال تابع لنطاق موثّق.
- ضبط WEB_ORIGINS على أصل الويب المنشور في Vercel.

## إعداد الواجهة

انسخ `.env.example` إلى `.env.local` ثم ضع عنوان HTTPS الحقيقي لبوابة API وخادم Matrix. لا تضع مفاتيح Resend أو أسرار الخادم في متغيرات VITE؛ هذه مفاتيح خادمية فقط.

## إعداد بوابة الهوية

أضف هذه المتغيرات إلى بيئة تشغيل gateway:
- `RESEND_API_KEY`: مفتاح Resend بصلاحية إرسال فقط.
- `RESEND_FROM`: عنوان الإرسال على نطاق تم التحقق منه في Resend.
- `WEB_ORIGINS`: أصل موقع الويب المنشور.
- متغيرات قاعدة البيانات وRedis وMatrix والأسرار الموجودة في إعدادات البوابة.

تستخدم الواجهة:
- `POST /v1/auth/email/start` لإرسال رمز من 6 أرقام.
- `POST /v1/auth/email/verify` للتحقق وإنشاء/استرجاع جلسة Matrix.

الرمز صالح لخمس دقائق، مع حد لإعادة الإرسال ومحاولات التحقق.

## التشغيل المحلي

```bash
cd web
cp .env.example .env.local
npm install
npm run dev
```

## القيود الحالية

هذه النسخة لا تزال بحاجة إلى نشر الخدمات الخلفية وضبط أسرارها وعناوين HTTPS قبل أن يعمل الدخول فعلياً. واجهة الويب لا تنشر FastAPI أو Synapse تلقائياً. يجب اختبار تسجيل الدخول على بريد تملكه، ثم اختبار المحادثات المشفرة على جهازين قبل الاستخدام مع بيانات حساسة.
