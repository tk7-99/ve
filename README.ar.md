# دَزّة | DAZZA — حزمة تطوير 0.1.0

**من العراق... دزّ رسالتك للعالم.**

هذه حزمة مصدر Flutter وخادم مستقل، وليست تطبيقاً مكتملاً أو إصداراً جاهزاً للنشر. تحتوي على تنفيذ أولي مرتبط بواجهات خدمات حقيقية، دون مستخدمين وهميين أو تسجيل دخول محاكى. لم تُشغّل الخدمات على نطاق عام ولم تُجرّب المحادثة بين جهازين. يتوقف الدخول عند عدم إعداد مزوّد SMS، ويتوقف إرسال الرسائل إذا لم يكن التشفير جاهزاً.

## ما تحتويه الحزمة

- `mobile/`: مشروع Flutter أصلي مع ملفات Android وiOS، واجهات عربية RTL وإنجليزية، وضعين فاتح وداكن وحجم خط قابل للتعديل.
- `gateway/`: بوابة Python/FastAPI للتسجيل الهاتفي عبر Twilio Verify، مع حدود للمحاولات وإعادة الإرسال، وتحقق من جلسة Matrix للبحث عن المستخدمين.
- `compose.yaml` و`infra/`: Synapse 1.164.1 وPostgreSQL وRedis وCaddy لإنهاء TLS. لا يوجد منفذ عام لقاعدة البيانات أو Redis أو واجهات إدارة Synapse.
- `scripts/bootstrap.py`: إنشاء إعدادات الخادم وأسرار عشوائية محلياً دون طباعتها. يرفض الكتابة فوق إعدادات قائمة.
- `docs/ARCHITECTURE.md`: التصميم وحدود الثقة ومطابقة البيانات مع متطلبات المشروع.
- `docs/STATUS.md`: الميزات المنفذة جزئياً، وما لم يُنفّذ، والاختبارات المطلوبة.
- `brand/`: أصل شعار بصيغة SVG وأيقونة PNG؛ تم وضع الأيقونة في مشاريع الهاتف.

## حدود هذا الإصدار

الكود يشمل التسجيل الهاتفي، أسماء المستخدمين، تسجيل الدخول والخروج، المحادثات الفردية، إنشاء المجموعات والدعوات، الرسائل النصية، الرد والتعديل والنسخ والتفاعل، إرسال ملفات مشفرة وتنزيلها، مؤشر الكتابة، البحث في المحادثات والرسائل المحمّلة، وتعديل الاسم.

**وجود الكود ليس إثباتاً بأن هذه المسارات تعمل على هاتف فعلي.** لم يُختبر تكامل SMS أو تشغيل Synapse/PostgreSQL في هذه البيئة. ليس ضمن المنجز: المكالمات، الحالات، القنوات، المجتمعات، إشعارات الخلفية، لوحة الإدارة، مزامنة جهات الاتصال، استعادة مفاتيح التشفير والتحقق المتبادل من الأجهزة. لا تُرسل بيانات حساسة قبل استكمال دورة الأمان والاختبارات.

## المتطلبات الخارجية

1. خادم Linux مع Docker Engine وDocker Compose، ونطاقان مثل `matrix.your-domain.com` و`api.your-domain.com` يشيران إليه.
2. فتح 80 و443 للوصول العام، ومنافذ الإدارة عبر شبكتك الخاصة فقط.
3. حساب Twilio وVerify Service صالحان، مع دعم إرسال SMS إلى العراق. التجربة الفعلية ترسل رسائل مدفوعة حسب حسابك؛ الاختبارات المرفقة لا ترسل رسائل.
4. Flutter SDK؛ استُخدم Flutter **3.47.9** مع Dart **3.13.7** للتحليل واختبارات الواجهة. Android SDK وJDK لبناء Android، وmacOS وXcode وحساب Apple Developer لبناء وتوقيع iOS.
5. حفظ نسخ احتياطية آمنة من أسرار الهوية وقاعدة البيانات. فقدان أو تغيير `IDENTITY_SECRET` أو `PASSWORD_SECRET` دون خطة ترحيل يعطّل الوصول للحسابات القائمة.

## تشغيل الخادم

نفّذ من جذر المشروع على خادمك، بعد تعيين DNS:

```bash
python3 scripts/bootstrap.py --matrix-domain matrix.your-domain.com --api-domain api.your-domain.com
```

سيُنشئ `.env` و`infra/generated/homeserver.yaml` بصلاحيات مقيّدة. املأ القيم التالية في `.env` باستخدام محرر آمن على الخادم، ولا تضعها في Git أو تطبيق الهاتف:

```dotenv
TWILIO_ACCOUNT_SID=
TWILIO_AUTH_TOKEN=
TWILIO_VERIFY_SERVICE_SID=
```

صورة Synapse الرسمية تعمل افتراضياً بالمستخدم 991؛ اسمح لها بقراءة ملف الإعدادات مع إبقاء الملف خاصاً. راجع UID للصورة عند تغييرها:

```bash
sudo chown 991:991 infra/generated/homeserver.yaml
sudo chmod 600 infra/generated/homeserver.yaml
chmod 600 .env
docker compose config --quiet
docker compose up -d --build
```

لا تستخدم `docker compose config` دون `--quiet` في سجل مشترك، لأنه قد يعرض متغيرات البيئة. إعدادات TLS تعتمد على نجاح إصدار شهادة Caddy وتوجيه DNS. راجع السجلات محلياً عند فشل الإقلاع، دون نسخ رموز الوصول أو بيانات الحسابات.

يُطبّق `infra/init.sql` فقط عند إنشاء مجلد PostgreSQL جديد. لا تحذف مجلد قاعدة البيانات لإعادة تطبيق مخطط؛ استخدم ترحيلاً منظماً للحفاظ على بيانات المستخدمين. إنشاء حسابات إدارة Synapse وإدارة صلاحياتها ليست جزءاً من بوابة الهاتف.

## تشغيل الهاتف

من مجلد `mobile/`:

```bash
flutter pub get
flutter run --dart-define=DAZZA_API_URL=https://api.your-domain.com --dart-define=DAZZA_MATRIX_URL=https://matrix.your-domain.com
```

العنوانان إعدادات عامة وليسا أسراراً. يجب أن يطابق عنوان Matrix قيمة `MATRIX_PUBLIC_URL` في إعدادات الخادم. لا تُضمّن مفاتيح Twilio أو أسرار التسجيل أو كلمات مرور PostgreSQL في `--dart-define`.

للتجربة بين شخصين، شغّل التطبيق على جهازين وسجّل كل شخص برقم يملكه. اختَر أسماء مستخدمين مختلفة. أنشئ محادثة باسم المستخدم الآخر واقبل الدعوة من جهازه. تأكد من نجاح النصوص والملفات والاستئناف بعد انقطاع الإنترنت. لا تعتبر نجاح ظهور شاشة الدخول دليلاً على نجاح هذه الخطوات.

## بناء Android وiOS

لبناء APK تطويري بعد تثبيت Android SDK:

```bash
flutter build apk --debug --dart-define=DAZZA_API_URL=https://api.your-domain.com --dart-define=DAZZA_MATRIX_URL=https://matrix.your-domain.com
```

إصدار النشر لا يستخدم مفتاح debug. أضف `mobile/android/key.properties` محلياً وفق الصيغة التالية مع مفتاحك الحقيقي، ثم استخدم `flutter build appbundle --release` مع تعريفي العناوين:

```properties
storeFile=/secure/path/dazza-upload.jks
storePassword=YOUR_LOCAL_VALUE
keyAlias=YOUR_ALIAS
keyPassword=YOUR_LOCAL_VALUE
```

هذه القيم تمثيلية وليست اعتماداً صالحاً. الملف ومفاتيح التوقيع مستبعدة من Git والحزمة. راجع معرف الحزمة `app.dazza.dazza` قبل حجزه في المتجر. على macOS افتح مشروع iOS واضبط Team والتوقيع، ثم استخدم `flutter build ipa` مع العناوين. **لم يُنفّذ أي من بناءَي Android وiOS هنا.**

## الخصوصية والتشفير

المراسلة تستخدم Matrix وOlm/Megolm عبر Vodozemac؛ لم تُبتكر خوارزمية تشفير. تُنشأ المحادثات مع التشفير مفعلاً ويُرفض الإرسال لغرفة غير مشفّرة. قاعدة الهاتف المحلية تستخدم SQLCipher ومفتاحاً عشوائياً في مخزن الجهاز الآمن.

هذا لا يعني أن المنتج خضع لتدقيق أمني. بيانات العضوية والتوقيت وبعض أحداث الحالة تظل بيانات وصفية يراها الخادم. التحقق من الأجهزة، استعادة المفاتيح، قفل التطبيق والبصمة، سياسات الاحتفاظ، تنقيح السجلات ومقاومة إساءة الاستخدام على مستوى المنظومة تحتاج عملاً إضافياً. تسجيل الخروج قبل بناء استعادة المفاتيح قد يفقد القدرة على قراءة رسائل قديمة؛ التطبيق يعرض تنبيهاً قبل ذلك.

الوسائط مخزنة حالياً في مجلد Synapse دائم، وليست في Object Storage مستقلة. الربط بمخزن S3 وسياسات الوصول والنسخ الاحتياطي لم يُنفّذ بعد. يجب استكمال سياسة الخصوصية وشروط الاستخدام قبل إطلاق عام.
