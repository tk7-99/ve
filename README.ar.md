# دَزّة | DAZZA

**من العراق... دزّ رسالتك للعالم.**

تطبيق مراسلة عراقي بواجهة Flutter وخادم Matrix/Synapse وبوابة FastAPI. هذه نسخة تطوير، وليست بعد نسخة إنتاجية أو APK مهيأ للاتصال بخادم حقيقي.

## ما يتضمنه المستودع

- mobile/: تطبيق Flutter لأندرويد وiOS.
- gateway/: بوابة الهوية وواجهات الحساب.
- Matrix/Synapse: الغرف والرسائل والمزامنة والتشفير.
- PostgreSQL: بيانات Synapse وملفات هوية DAZZA في قاعدتين منفصلتين.
- Redis: رموز البريد المؤقتة وحدود المحاولات.
- Resend: إرسال رموز التحقق إلى البريد الإلكتروني.
- Caddy: إنهاء TLS وتوجيه طلبات API وMatrix.

## متطلبات الخادم

خادم Linux مع Docker Engine وDocker Compose، نطاقان DNS يشيران إلى الخادم، ومنافذ 80 و443 متاحة. استخدم نطاقاً مستقلاً لخدمة Matrix ونطاقاً لبوابة API.

## إعداد أول مرة

من جذر المشروع:

    python3 scripts/bootstrap.py --matrix-domain chat.example.com --api-domain api.example.com

يُنشأ ملف .env وإعداد Synapse. السكربت يرفض الكتابة فوق ملف .env موجود حتى لا يستبدل الأسرار.

افتح .env وأضف بيانات Resend في الخادم فقط:

    RESEND_API_KEY=re_...
    RESEND_FROM=DAZZA <login@your-domain.example>

يجب أن يكون نطاق الإرسال مفعّلاً ومتحققاً لدى مزود البريد. لا ترسل هذه القيم لأحد ولا تضعها في تطبيق Flutter أو GitHub كقيمة نصية داخل الكود.

شغّل فحص الإعدادات ثم الخدمات:

    docker compose config --quiet
    docker compose up -d --build

تحقق من حالة الحاويات:

    docker compose ps
    docker compose logs --tail=100 gateway synapse caddy

اختبر بوابة الهوية:

    curl https://api.example.com/health

يجب أن تكون النتيجة JSON تفيد أن خدمة DAZZA تعمل. اختبار وصول البريد يتطلب طلب رمز من التطبيق أو اختباراً مصرحاً به إلى مسار البريد.

## بناء تطبيق Android

من مجلد mobile/:

    flutter pub get
    flutter analyze
    flutter test
    flutter build apk --debug --dart-define=DAZZA_API_URL=https://api.example.com --dart-define=DAZZA_MATRIX_URL=https://chat.example.com

استبدل النطاقين بعناوين الخادم الفعلية. ينتج APK في mobile/build/app/outputs/flutter-apk/app-debug.apk. هذا بناء Debug للاختبار، وليس نسخة متجر موقعة.

## فحوصات GitHub Actions

يوجد سير CI لفحص اختبارات Python وتحليل واختبار Flutter وبناء APK Debug عند الدفع إلى فرع التطوير أو فتح Pull Request. عندما لا تكون عناوين الخادم الفعلية متاحة، يستخدم CI نطاقات .invalid فقط لفحص قابلية البناء؛ لا تتصل هذه النسخة بخدمة DAZZA حقيقية. لا يُرفع APK كملف قابل للتجربة إلا عند ضبط Repository Variables باسم DAZZA_API_URL وDAZZA_MATRIX_URL على عناوين HTTPS الفعلية.

## المراسلة والوسائط

- الرسائل النصية والمجموعات الأساسية عبر Matrix.
- الصور ترسل مشفّرة وتظهر بمعاينة داخل المحادثة.
- الرسائل الصوتية يمكن تسجيلها وإرسالها وتشغيلها داخل المحادثة، مع أذونات الميكروفون في Android وiOS.
- الملفات العامة ترسل حتى 20 MB من الواجهة الحالية.
- تشغيل الفيديو داخل المحادثة، المكالمات الصوتية والمرئية، الحالات والقنوات والإشعارات الخلفية ولوحة الإدارة ما تزال ضمن الأعمال المتبقية.

## التسجيل

البريد الإلكتروني هو وسيلة التسجيل والدخول الوحيدة في الإصدار الحالي:
1. يدخل المستخدم بريده.
2. يصل رمز تحقق من ستة أرقام.
3. الحساب الحالي يدخل بالرمز فقط.
4. الحساب الجديد يحدد اسمه واسم المستخدم.

إعداد Resend غير مضمن في Git؛ يجب إضافته إلى .env على الخادم ثم إعادة تشغيل gateway. لا يوجد تسجيل أو دخول برقم الهاتف أو SMS في هذا الإصدار.

## الأمان والحدود المعروفة

- لا تفتح PostgreSQL أو Redis أو Synapse على الإنترنت مباشرة.
- لا تضع أسرار Resend أو Synapse في التطبيق.
- التحقق من الأجهزة واستعادة مفاتيح E2EE غير مكتملين.
- لم يُختبر وصول البريد أو تشغيل Docker أو المراسلة بين جهازين فعليين ضمن آخر تعديلات المشروع.
- لا تستخدم النسخة لمحادثات حساسة أو إطلاق عام قبل اختبارات التكامل ومراجعة الأمان والنسخ الاحتياطي.
