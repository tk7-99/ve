# بنية دَزّة | DAZZA

## البنية الحالية

التطبيق الأصلي Flutter، وخدمات الهوية والمراسلة تعمل على خادم منفصل. لا تُخزَّن الرسائل في جداول مخصصة داخل بوابة الهوية؛ خادم Matrix/Synapse يدير الغرف والأحداث والأجهزة والتشفير والمزامنة.

    Flutter app
      ├── HTTPS ── Caddy ── FastAPI identity gateway
      │                         ├── Resend email API (OTP)
      │                         ├── Redis (temporary challenges / cooldown / rate limits)
      │                         ├── PostgreSQL (DAZZA identity profiles)
      │                         └── internal Synapse registration/login
      │
      └── HTTPS ── Caddy ── Matrix Client API ── Synapse ── PostgreSQL (Synapse)
                                                        └── encrypted media volume

## تسجيل الحساب والبريد

1. المستخدم يدخل بريده الإلكتروني؛ الخادم يطبّع النص إلى lowercase ويحسب HMAC للبريد باستخدام سرّ خادمي.
2. لا يُخزّن عنوان البريد الخام في جدول profiles. يحتفظ Redis مؤقتاً بعنوان البريد داخل تحدٍّ مدته خمس دقائق، مع بصمة HMAC لرمز التحقق.
3. يرسل Resend رمزاً من ستة أرقام. الرمز لا يُعاد إلى التطبيق ولا يُخزّن كنص صريح.
4. توجد حدود إرسال لكل عنوان بريد ولكل عنوان IP، وفترة انتظار 60 ثانية، وحد لمحاولات إدخال الرمز.
5. بعد التحقق، إذا كان البريد مرتبطاً بحساب سابق، يمكن للمستخدم الدخول من دون إدخال الاسم أو اسم المستخدم. الحساب الجديد يجب أن يختار اسم مستخدم فريداً واسماً ظاهراً.
6. ينشئ الخادم مستخدم Matrix غير إداري أو يسجّل دخوله باستخدام shared-secret registration protocol، ثم يعيد access token وdevice ID إلى التطبيق.
7. يجب إعداد RESEND_API_KEY وRESEND_FROM في بيئة الخادم. من دونهما يرجع المسار email_not_configured. لا يوجد تسجيل عبر الهاتف أو SMS في واجهة DAZZA أو API الهوية الحالية.

المسارات العامة:
- POST /v1/auth/email/start
- POST /v1/auth/email/verify
- GET /v1/users/{username} (يتطلب Matrix Bearer token)
- GET /health

## المراسلة والوسائط والتشفير

- Matrix/Synapse يدير الغرف والأعضاء والأحداث والأجهزة والمزامنة.
- Flutter يستخدم حزمة Matrix وVodozemac، مع قاعدة محلية مشفرة عبر SQLCipher ومفتاحها محفوظ في Secure Storage.
- واجهة التطبيق توقف إرسال الرسائل والوسائط إذا لم يكن التشفير مفعلاً للعميل والغرفة.
- الرسائل النصية تدعم الرد والتعديل والنسخ والتفاعل ومؤشر الكتابة. عرض بعض علاقات الرسائل ما يزال يحتاج إكمالاً.
- الصور تُرسل كمرفقات Matrix مشفرة وتُعرض بمعاينة داخل المحادثة بعد فك تشفيرها على الجهاز. الضغط على الصورة يتيح مشاركتها.
- الملفات العامة تُرسل كمرفقات، بحد حالي 20 MB من واجهة التطبيق. لا يوجد عارض عام مخصص لكل أنواع الملفات.
- الرسائل الصوتية تسجَّل محلياً بصيغة AAC/M4A باستخدام record، ثم تُرسل عبر Matrix كوسائط مشفرة. تُنزّل وتُفك محلياً عند التشغيل عبر just_audio، وتُحذف ملفات التسجيل والتشغيل المؤقتة عند الإرسال/انتهاء التشغيل/إغلاق واجهة المحادثة.
- تشغيل الفيديو داخل المحادثة غير مكتمل؛ وسائط الفيديو العامة لا تزال تظهر كملف قابل للمشاركة/التنزيل.
- ما يزال التحقق المتبادل من الأجهزة واستعادة مفاتيح التشفير غير مكتملين؛ لذلك لا تعتبر النسخة جاهزة للبيانات الحساسة أو الإطلاق العام لمجرد وجود E2EE في SDK.

## قواعد البيانات

infra/init.sql ينشئ قاعدة dazza_identity وجدول profiles فقط. Synapse ينشئ مخططه وترحيلاته بنفسه داخل قاعدة synapse. لا تنشئ جداول رسائل موازية؛ ذلك سيكرر مسؤولية Matrix وقد يتعارض مع مزامنة الأحداث المشفرة.

| المجال | مكان البيانات | الحالة |
|---|---|---|
| الهوية واسم المستخدم | dazza_identity.profiles | بريد HMAC، اسم مستخدم، اسم ظاهر، Matrix user ID |
| المحادثات والأعضاء | Matrix rooms وmembership events | محادثات فردية ومجموعات أساسية |
| الرسائل والتعديلات والردود | Matrix events | نص ورد وتعديل وتفاعل؛ تحسين عرض العلاقات متبقٍ |
| الصور | Matrix media repository | إرسال مشفر ومعاينة داخل المحادثة |
| الصوت | Matrix media repository + ملفات مؤقتة محلية | تسجيل AAC وإرسال وتشغيل داخل المحادثة |
| الفيديو والملفات الأخرى | Matrix media repository | إرسال وتنزيل؛ مشغل فيديو مخصص غير مكتمل |
| الأجهزة والجلسات | Matrix devices وaccess tokens | جلسة محفوظة؛ إدارة الأجهزة غير مكتملة |
| الإعدادات المحلية | SharedPreferences | اللغة والثيم وحجم الخط |
| الحظر والبلاغات والأصدقاء | غير منفذة بعد | تتطلب تصميم خدمة وصلاحيات |
| الحالات والقنوات والمجتمعات | غير منفذة بعد | لا توجد واجهات إنتاجية |
| المكالمات | غير منفذة بعد | لا WebRTC أو TURN |
| إشعارات الخلفية | غير منفذة بعد | لا FCM/APNs أو Push Gateway |
| لوحة الإدارة | غير منفذة بعد | لا توجد لوحة DAZZA مستقلة |

## تشغيل الخدمات

- compose.yaml يشغّل PostgreSQL وRedis وSynapse وFastAPI وCaddy.
- scripts/bootstrap.py ينشئ .env وإعداد Synapse لأول مرة، ويرفض استبدال .env موجود.
- لا تفتح منافذ PostgreSQL أو Redis أو Synapse الداخلية مباشرة على الإنترنت.
- يجب نشر Caddy مع DNS صحيح وTLS صالح لنطاق Matrix ونطاق API.
- يجب إضافة إعدادات Resend للخادم فقط، وعدم تضمين مفاتيح Resend أو أسرار Matrix في تطبيق Flutter.
- النسخ الاحتياطي والاستعادة ومراقبة التشغيل واختبار الضغط لم تُثبت بعد.

## بناء التطبيق

من مجلد mobile/:

    flutter pub get
    flutter analyze
    flutter test
    flutter build apk --debug \
      --dart-define=DAZZA_API_URL=https://api.example.com \
      --dart-define=DAZZA_MATRIX_URL=https://matrix.example.com

استبدل النطاقين بنطاقات الخادم الفعلية. التطبيق يرفض عناوين HTTP، ولا يعرض تسجيل دخول وهمياً عند غياب الإعدادات.

## ما يمنع الإطلاق

- إعداد Resend والتحقق من وصول البريد فعلياً.

- تسجيل حسابين حقيقيين واختبار الرسائل والصور والصوت والتشفير بين جهازين.

- إضافة إشعارات الخلفية، المكالمات، الحالات، القنوات، الأصدقاء، الحظر والبلاغات.
- إنشاء لوحة الإدارة، النسخ الاحتياطي، المراقبة، اختبارات الضغط، وتوقيع إصدار Android/iOS.
